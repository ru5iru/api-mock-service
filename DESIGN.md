# Design System: MockDeck

## Overview

**Creative North Star: "The Warm Operating Workbench"**

The implemented v7 system follows the approved HTML prototype's final cascade: warm dark grounds, amber commands, compact typography, continuous panes and measured tactile depth. Light uses warm pale equivalents; System resolves the same two maps. This records the pinned reference with no new visual direction.

MockDeck is an operator's exact-request mocking tool. The persisted product-contract equivalent is [Product contract in the UI guide](docs/UI_GUIDE.md#product-contract). Server persistence, real recorded evidence, independent draft scopes and existing Laravel/Livewire/Alpine behavior constrain presentation. Prototype fixture content and browser-local demos do not replace application semantics.

**Key Characteristics:**

- Warm paired themes with amber emphasis and restrained semantic exceptions.
- Compact system UI type and self-hosted JetBrains Mono for machine values.
- Continuous work surfaces with inset editors and selectively elevated controls.
- Explicit selected, disabled, loading, error and save states with existing keyboard behavior.

Source truth is `public/css/tokens.css`, the final cascade in `public/css/app.css` and the actual Blade components. The approved `docs/ui-redesign/MockDeck-Desktop-UI-v7.html` governs visual forms it defines; its guide fills gaps, then existing app presentation. Those reference/evidence files remain ignored. [UI_GUIDE.md](docs/UI_GUIDE.md) supplies the complete token inventory and workflow recipes. [UI_UPGRADE.md](docs/UI_UPGRADE.md) preserves historical v6 evidence, not current visual authority.

Frontmatter records reused primitives extracted from shipped CSS. The `light-` and `dark-` keys are paired alternatives of each semantic token. Component entries show the dark mapping; live components use theme-aware variables. The primary fill entry is its semantic fallback: the full normative gradient, borders, shadows, motion and responsive geometry are carried in the sidecar and CSS.

## Colors

### Primary

Warm amber carries commit actions, active navigation, selected context and focus. Use accent, hover, subtle, border and link roles with their matched on-accent foreground. Selection foreground/background and field-focus border are separate roles. Preserve the prototype primary button's gentle gradient rather than flattening it into its fallback fill.

### Neutral

Warm canvas, chrome and sidebar set the frame; subtle, inset, raised, hover and pressed surfaces distinguish working layers. Ordinary borders, subtle separator lines, strong boundaries and field boundaries are distinct. Primary, muted and subtle text remain readable in both themes. Disabled controls use opaque paired tokens.

Success, warning, danger and information use matching background/foreground/border triplets. Blue remains an information exception; purple remains a PUT exception. GET/PATCH use green, POST amber, DELETE danger red and HEAD/OPTIONS neutral. Preserve verb/status text and non-color state cues. Technical syntax uses amber keys/flags, green strings/URLs and muted headers.

**The Paired Theme Rule.** Change both semantic maps together. Keep each color's role; do not scatter prototype literals into feature styles.

**The Contextual Boundary Rule.** Verify field and focus contrast against the actual adjacent surface in each state. A boundary passing on its inset field does not certify it on every pressed or raised surface.

## Typography

**Body Font:** System UI using the exact stack in `typography.body`.
**Label/Mono Font:** Self-hosted JetBrains Mono using the exact stack in `typography.code`.

The hierarchy is compact and operational. Body is the regular reading role; title and brand provide restrained semibold emphasis; labels and controls use medium weight; support text and small commands use the smallest role. The shared scale is 11/12/13/14/16/20px, with an observed 15px empty-state title. No visible text is smaller than the support role. Technical editor text uses the code role and generous code leading; URLs, paths, headers, JSON, hashes and IDs use mono even within UI rows.

Use tabular numerals for comparable measurements and disable ligatures in code and identity-heavy lists. Long identities wrap or scroll within their component; the source request strip may ellipsize with its full-value native title. JetBrains Mono glyph metrics deliberately differ from the prototype's platform mono.

**The Machine Value Rule.** Preserve exact technical bytes and readable identities. A syntax layer, preview or copy affordance must not imply formatting, execution or persistence that the underlying control does not perform.

## Layout

The shell retains a topbar (46px), fixed bottom status bar (25px), icon rail and contextual sidebar. Rail/context are 52px/252px normally; context is 272px at widths of at least 1550px; rail/context become 46px/220px at 1150px and below. At 950px and below context becomes a drawer and the work area offsets only by the rail. At 650px and below the rail is 40px and remains visible alongside the labelled Menu. Hidden drawer content stays inert; Escape restores toggle focus. Persisted collapse preference and temporary drawer state remain separate.

Pane gutters are 20px, reducing to 14px at 650px. Four-pixel spacing steps and named optical offsets reproduce the reference without rounding every detail to a generic grid. Persistent topbar width is stable across pages with different scroll owners.

The editor uses a 65px desktop heading, 42px tab region and full-width request strip with a 40px inset control (76px desktop strip including padding). Above 650px request/response panes scroll independently inside a measured viewport; minimum-zero tracks are .92fr/1.08fr, becoming 1fr/1.15fr at 1550px. Save and existing Cancel sit in the heading. At 650px and below panes stack in request-first order, the outer viewport owns scrolling and the existing bottom Save/Cancel bar remains. Existing phone controls retain 44px targets. This extension does not enlarge every rail/footer affordance: the footer Shortcuts target remains 24px inside its bar.

Callback heading/form and Settings use an 850px bound. Callback's existing response selector is a compact full-width strip above the bounded form; delivery explanations follow URL controls. Settings pairs Collection/Priority and gives Tags a full-width section; paired metadata stacks at 740px. Response/schema/rule fields respond to pane container width with minimum-zero tracks.

Logs use a five-column request table with endpoint/Environment metadata beneath the target, a 69px compact row pitch and an 84px Comfortable option. Copy stays compact on desktop; stacked phone rows retain actions/evidence. The inspector sits beside the list above 780px and uses the existing focused inspector flow below. Mobile selects form two columns and live/pause state stays compact. Export selection/options use 1.65fr/1fr tracks and stack at 720px; Import and Review plan remain subsequent anchor sections. Documentation has a 1040px maximum workspace and 60ch reading measure. Registry rows remain continuous; filters, bulk controls and metadata wrap at their existing responsive thresholds.

**The Scroll Ownership Rule.** Give each task one measured outer viewport or the documented independent pane scrollers. Bound tables, code and overlays within their component; preserve focus, sticky action clearance and reading order when panes stack.

## Elevation & Depth

The v7 material combines warm tonal layers with small structural shadows. Work panes and registry rows remain flat and square; chrome, controls, selected explorer entries, inset code/fields, inspectors, menus, dialogs and bottom action bars use named roles. Dark mode retains the prototype's shadows. The former v6 rule that removed dark ambient depth is superseded.

Numbered shadows step from low control depth through hover/menu depth to high dialog/drawer depth. Highlight edges, inset wells/fields, pressed controls, inspector edges and primary-button elevation are distinct recipes. Exact paired values live in `.impeccable/design.json` and `public/css/tokens.css`. A solid focus outline remains visible alongside an optional halo; `--focus-ring` is a color and `--shadow-focus` is the halo.

Control transitions use shared easing, 140ms feedback, 180ms base and 80ms press motion with a half-pixel press shift where implemented. Reduced motion collapses transitions/animation; theme switching suppresses transitions. Persistent shell surfaces have no decorative entrance motion.

**The Selective Depth Rule.** Preserve the prototype's primary-button gradient and tactile control states while keeping continuous working panes free of decorative card lift.

## Shapes

The primitive radius scale includes small, medium, large and pill roles. Components keep their own established geometry: inputs (4px), buttons (5px), explorer entries (6px), menus (8px), dialogs (10px) and toasts (6px). Tags use the small (3px) shape rather than the former pill treatment. Switch tracks and avatar/status circles retain their silhouettes. Work panes and registry rows are square with fine (1px) boundaries and 2px selected edges. Global focus uses a 2px outline with 3px offset; field focus has its observed 2px offset.

## Components

### Buttons

Tactile compact controls: standard height 32px, small 26px, large 36px; standard padding 0/12px. Use the control type role and shared icon gap. Primary is amber gradient with its own border/highlight/shadow across rest, hover and press. Secondary uses the control surface; tertiary is transparent/muted; danger is outlined except the filled destructive confirmation action. All variants retain shared focus and opaque disabled recipes, explicit form ownership and loading targets.

### Inputs / Fields

Inset fields pair label, control, helper and error. Standard inputs/selects are 32px with 5px/9px padding and the input radius; retained mobile variants reach 44px. Native selects reserve chevron space and keep semantics/forced-color fallback. Hover uses the accent boundary; focus combines focus border, solid outline and optional halo on the inset surface. Errors retain destination hooks and a non-color cue. Switches use a 30x18px track, 12px thumb and 3px inset while retaining bindings and accessible labels.

### Chips / status

Tags use a 20px minimum height, support text, fine boundary and 3px radius. Selected tag inputs retain keyboard behavior. Status/method badges use semantic pairs; registry/transfer verbs use the reference's restrained text treatment. Dots never replace an accessible state name.

### Navigation

Rail links use centered SVG icons, accessible labels and current-page state. Resting links are muted; hover uses the shared surface; active uses amber, selected ground, highlight and edge marker. The explorer is the real paginated filtered endpoint list with search, collection/Unfiled selection and wrapped identities. Selected entries use subtle accent surface, inset amber edge and small elevation.

Tabs retain amber underline, selected state, roving focus and Arrow/Home/End behavior. Editor / Callback / Settings remain primary tasks; Request / Matching remain inner sections and Responses the sibling region. Menus/disclosures preserve native summary semantics, Escape, viewport clamping, focus restoration and existing controllers.

### Cards / Containers

Continuous square panes and separator rows replace isolated dashboard cards. Selected rows use the accent edge; hover uses the shared surface. Padding follows pane gutters and spacing tokens. The compact auth/error shell is a separate dialog-radius, high-elevation context. Dialogs preserve their native controller; destructive confirmations focus Cancel. Toasts retain their live region, radius and elevation.

### Technical editor and supporting workspaces

Static response bodies use one inset code canvas and a presentation-only syntax/gutter layer over the original textarea. JavaScript failure and forced colors expose the readable native textarea. Static/Template, Builder/JSON, schema/Faker, seed/sample, selection strategy, faults and history reuse existing controls and draft scopes. Extensions use the same field, separator, code, menu and notice language.

The request strip retains raw cURL Edit request parsing. Explicit response selection, Cancel, Copy, recorded log fields, all filters, Environment secrets/drafts, import preview/acknowledgement/apply/undo and server saves remain functional extensions. Preview actions never become a save claim. No prototype-only execution preview, CSV, local configuration persistence or collection CRUD is introduced.

## Do's and Don'ts

### Do:

- **Do** follow the approved prototype's final cascade, then guide recipes, while retaining application behavior.
- **Do** use paired semantic tokens, self-hosted JetBrains Mono and measured shell/component geometry.
- **Do** preserve native controls, focus visibility, selected text/ARIA cues, reduced motion and forced-color fallbacks.
- **Do** retain independent draft/save scopes, recorded evidence and existing recovery actions.
- **Do** verify actual responsive states in both themes and System; source tests alone do not certify appearance.

### Don't:

- **Don't** restore stale v6 shell dimensions, 1100px editor stacking, pill tags or flat/no-gradient control rules.
- **Don't** change technical bytes, parser/validation semantics or server persistence to mimic prototype demos.
- **Don't** flatten the defined amber primary gradient or remove selective elevation.
- **Don't** claim pixel-identical content across different fixtures or complete accessibility from automated checks.
- **Don't** canonize the inherited ordinary-table `tr[aria-expanded]` axe finding as a component rule; its inspector/keyboard hooks remain preserved pending a separately scoped semantic change.

Validation boundaries: recorded frontend/setup/token checks and browser evidence are described in the UI guide and ignored `docs/ui-redesign/after/qa/RESULTS.md`. The full PHP run has one reproduced baseline temporary-HTTPS MCP failure; optional baseline save-race/restore/import findings also remain. No physical screen-reader test, deployment or unrelated backend certification is claimed. These limitations are not new design rules.
